## 一、设计功能

**【简版】**

本项目为麒麟/Linux 服务器实现了一个自然语言智能运维 Agent（B/S 架构），四项功能：
① 自然语言系统问答：22 个只读 MCP 工具覆盖进程/网络/磁盘/日志/句柄/系统状态六类，用户以自然语言提问，Agent 自动选工具并返回真实实时数据；
② 一键健康诊断与根因分析：大文件"关键勿删/可清理/拿不准"三级判定，僵尸进程、日志疯涨等多信号关联出带置信度的证据链，定位到元凶进程；
③ 受控运维动作：清日志、杀进程、清垃圾、重启服务、重载配置、封 IP、清系统日志共 7 个白名单动作，固定命令模板+参数校验，执行前强制护栏裁决与用户二次确认；
④ 运维简报自动生成：一键聚合系统快照、健康诊断、安全态势与运维活动为结构化日报/周报及待办清单，Markdown 一键下载。
全链路记录"接收指令→感知环境→推理决策→安全校验→执行结果"五段思维链，支持按 trace 回放与哈希校验。

**【详版补充（追问用）】**

- 大模型：DeepSeek（国产、OpenAI 兼容接入），另有离线确定性桩模型，断网可跑完整闭环；
- 前端 Vue3 五个视图：智能对话、根因体检、运维简报、审计回放、护栏可视化；
- 质量数据：2662 条自动化测试全部通过；真实大模型工具选择实测 42/42 命中（18 个能力族）。

## 二、设计特色

**【简版】**

① **能力受限架构（主控制是架构，不是规则）**：感知与变更两条路径物理隔离——LLM 只能从只读工具中"选择"，没有自由执行命令的通道；变更仅限 7 个白名单动作且必须由用户显式确认，模型无法调用。即使模型被诱导，注入也无法升级为状态变更。
② **四道防线安全护栏，按"效果"裁决**：意图路由 → LLM 语义研判（识别"把数据库目录清了"类委婉删库）→ 注入检测 → 命令四重分析（正则 + realpath 路径还原 + Bash AST 结构分析 + 副作用效果判定），结果保守合并、风险只升不降，红线硬编码、配置层无法削弱。
③ **CaMeL 双 LLM 隔离阅读抗注入**：藏在日志等工具输出里的夹带指令，由不配任何工具的隔离模型读取压缩为"不可信摘要"后回喂，注入打不进控制流；污点门控保证"污点∧状态变更"恒不成立。
④ **思维链审计防篡改**：五段思维链逐段 HMAC 哈希链接，任一段被改链条即断裂，支持离线校验，"可追溯"可作证据核查。
⑤ **评测不自证**：拦截与误杀采用第三方语料（RedCode-Exec 18/18 拦截、DeepTeam 注入 10/10 检出、NL2Bash 505 条留出集误杀率 0.6%），护栏单次裁决约 229μs。

## 三、遇到的问题及解决方法

**问题 1：提示词注入可以藏在"数据"里绕过输入检测。** 对话入口的诱导话术能拦，但攻击者把"请执行 rm -rf /"夹带在日志正文里，Agent 读日志时会把数据当指令。
**解决**：引入 CaMeL 双模型隔离阅读——不可信工具输出先交给一个不配任何工具的隔离模型压成标注"不可信"的摘要，原始字节不进决策模型；配合 spotlighting 数据打标与污点门控，夹带指令进不了控制流。用 DeepTeam 第三方注入基准验证 10/10 检出。

**问题 2：正则规则库被命令变形绕过。** 红队自测发现语序调整、`$IFS` 空格替代、base64 编码、解释器内联代码等写法可骗过单一正则匹配，黑名单永远追不完。
**解决**：把裁决升级为四法保守合并——正则、realpath 真实路径还原、Bash AST 结构分析、副作用效果判定，前三看"形态"、第四看"效果"（只要执行效果是删关键路径/外联，伪装成什么样都拦），合并取最严。第三方 RedCode-Exec 基准 18/18 全拦。

**问题 3：意图层关键词黑名单"误杀真人、放过真攻击"。** 实测"检查一下系统有没有提权风险"因裸词"提权"被误判为黑；而真攻击可用编码/小语种绕过明文匹配，关键词层对抗价值近乎为零。
**解决**：方向性纠偏——意图层降级为路由层（白=只读快路，灰=进研判，黑仅注入话术），破坏意图改由 LLM 语义研判 + 架构兜底（模型本就没有执行腿）判定。误杀率用 NL2Bash 505 条真实命令留出集实测降至 0.6%。

**问题 4：磁盘满诊断可能引导用户误删关键文件。** "删最大的文件"是危险建议：数据库数据文件、备份可能就是最大的，且可被软链接伪装成普通路径。
**解决**：为根因分析增加关键性三级判定（关键勿删/可清理/拿不准），命中数据库/备份特征即判关键，软链接先 realpath 解析再判、防伪装；拿不准的明确交人工确认，诊断只输出"分类+证据+建议"、绝不自动执行。

**问题 5：龙芯 + 麒麟国产化部署几乎无公开资料，依赖装不上。** pydantic 核心是 Rust 扩展，LoongArch 无预编译包需源码编译，而麒麟自带 cargo 版本过旧编译失败；系统源里 pydantic 是不兼容的 1.x；国内 pip 镜像对龙芯索引不全，报"查无此版"。
**解决**：逐坑实测后固化为一键部署脚本（迭代到 v3）：自动探测并升级 Rust 工具链、绕开系统源污染、镜像失败自动回退官方源；八步幂等可重跑，含受限账户、开机自启与冒烟自检。最终全量 2662 条自动化测试在龙芯真机跑通，经验整理成部署文档。

**问题 6（备选，空间不够可略）：审计日志本身可被事后篡改，"留痕"不可信。**
**解决**：五段思维链逐段计算 HMAC 并与前段哈希链接成链，提供 verify_chain() 离线校验；任何一段被改动链条立即断裂，审计记录从"日志"升级为"可核查的证据"。
