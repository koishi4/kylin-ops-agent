# 软件工程课程报告 Word 生成（合工大格式）

## 关键约束（来自课程要求文档，必须满足）
- 正文**不少于 15 页**
- 路线选**面向对象软件分析与设计**（对 A2 这种 Agent 系统最自然，UML 图好画）
- 章节序号至多到三级（1 / 1.1 / 1.1.1）
- 评"优"(90-100)需"文档质量好 + 软件有难度"——A2 的安全护栏正好是"有难度"

## 格式规范（严格执行）

### 页面设置
- 上 2.5cm、下 2cm、左 2.5cm、右 2cm、装订线 0
- 正文页眉 2cm、页脚 2cm
- 正文 1.5 倍行距

### 字体字号
| 元素 | 字体 | 字号 | 其他 |
|---|---|---|---|
| 大标题(封面) | 黑体 | 2号 | 居中 |
| 摘要"摘要"二字 | 宋体加黑 | 小二号 | |
| 摘要正文 | 宋体 | 小四号 | 约200字 |
| "ABSTRACT"及英文 | Times New Roman | 小二/小四 | |
| 目录"目录"二字 | 宋体加黑 | 小二号 | |
| 一级标题(章) | 黑体加黑 | 小三号 | 居中，章间另起页 |
| 二级标题(节) | 黑体加黑 | 四号 | 居中，与上空一行 |
| 三级标题 | 黑体加黑 | 小四号 | 靠左 |
| 正文 | 宋体 | 小四号 | 1.5倍行距 |
| 图题/表题 | 宋体 | 5号或小5号 | 图题在图下居中，表题在表上居中 |
| 页码 | Times New Roman | 小五号 | 居中，连续编号 |
| 参考文献 | 宋体 | 小四号 | 顶格 |

### 图表编号
- 用章序号：图2.1 = 第2章第1图；表2.1 = 第2章第1表
- 图号与图题空一格，图题置于图正下方居中
- 表题置于表上方居中

### 参考文献著录格式
- 专著：主要责任者.题名[M].出版地:出版者,出版年.起止页码.
- 期刊：主要责任者.题名[J].刊名,出版年,卷(期):起止页码.
- 电子文献：主要责任者.题名.出版地:出版者(网址),日期.
- 按正文引用先后顺序编号 [1][2]...

## 报告章节结构（与 A2 内容的映射）

报告路线：面向对象分析与设计。建议章节及内容来源：

1. **绪论/引言**（≤3页）：运维痛点、AI 运维背景、本系统目标、国产化意义。素材见 docs/dev-log.md 开头。
2. **软件需求分析**
   - 2.1 UML 用例图：管理员↔Agent 的交互用例（查询状态、清理垃圾、诊断故障、危险操作被拦）
   - 2.2 活动图：一次运维请求的完整活动流（含护栏分支）
   - 功能需求：5条基本功能；非功能需求：确定性/可靠性/抗注入
3. **系统总体设计**（模块≥4）
   - 3.1 总体结构图 + UML 主设计类图（前端/后端/MCP Server/护栏/审计五大模块）
   - 3.2 主类工作原理：Agent 编排器、护栏引擎、执行器、审计器
4. **系统详细设计**
   - 4.1 系统包设计：各包的类图
   - 4.2 各类详细设计：护栏规则类、MCP工具类、思维链追踪类的类图 + 顺序图（一次"清理垃圾"的完整时序）
   - 4.3 接口设计：REST API 接口表、SQLite 表结构、前端界面
5. **系统测试与调试**
   - 黑盒：功能测试用例表（直接来自 pytest 用例）
   - 白盒：护栏规则覆盖测试、红队测试集结果（拦截率/误杀率表格）
   - 部署图、构件图、运行效果截图
6. **总结**：问题与解决（来自 dev-log）、收获体会
7. **参考文献**
8. **附录**：核心源代码清单（护栏规则、MCP工具，小四号宋体）

## 生成方式
用 docx skill（`/mnt/skills/public/docx/SKILL.md`）的 docx-js 方式创建。
- 默认字体设宋体，标题宋体/黑体按上表
- 一级标题章之间用 PageBreak
- UML 图先用 PlantUML/draw.io 画好导出 PNG，再 ImageRun 插入，配图号图题
- 表格用 docx Table，注意 dual width，表头浅色 ShadingType.CLEAR
- 生成后用 `python /mnt/skills/public/docx/scripts/office/validate.py` 校验

## 字号换算（docx-js 用半磅，size=磅数×2）
- 2号=44 / 小二=36 / 小三=30 / 四号=28 / 小四=24 / 5号=21 / 小五=18
（注：docx 的 size 单位是半点，常用近似值，以实际渲染微调）

## 一图两用原则
画 UML 图时同一批图既进课程报告，也进软件杯"软件功能设计文档"和答辩 PPT。命名统一放 docs/uml/。
